1. PROJECT OVERVIEW
================================================================================

This is a React + TypeScript frontend application for an Airport Telephone
CDR (Call Detail Record) Billing System. It provides a complete telecom
accounting console for managing:

  - Call Detail Records (CDR)
  - Call Management / Quality Records (CMR)
  - Extensions (SIP/Analog/IP phones)
  - Departments (cost centers)
  - Billing cycles & GST invoices
  - Rate plans / tariffs
  - User analytics & telecom reports
  - Device / hardware reports
  - System / trunk traffic reports
  - Data export (CSV / Excel / PDF workflows)

The application is currently a DEMO / PROTOTYPE frontend. It uses in-memory
mock data and simulated async services. It is structured so that mock services
can later be replaced with real Node.js / Express (or other) API calls.


================================================================================
2. PURPOSE & DOMAIN
================================================================================

Domain context: Airport telecommunications network accounting.

Typical use cases:
  - Track multi-department telephone extensions across airport terminals
  - Analyze incoming/outgoing trunk traffic (PRI / SIP)
  - Audit Local, Mobile, STD, and ISD usage
  - Calculate per-minute call costs with pulse billing and GST (18%)
  - Generate monthly invoices and department / individual bills
  - Monitor call quality (CMR: jitter, latency, packet loss)
  - Export filtered CDR/CMR archives for audit and compliance

Brand name in UI: "CDR Billing System" / "Telecom Analytics"

7. APPLICATION FLOW (END-TO-END)
================================================================================

1) User opens the app → Vite serves index.html → main.tsx boots React.

2) App wraps everything in BrowserRouter + AuthProvider.

3) AuthProvider checks localStorage key "aocc_auth":
     - If "true" → user treated as logged in (Admin User)
     - Else → unauthenticated

4) AppRoutes decides:
     - Not authenticated → redirect to /login
     - Authenticated visiting /login → redirect to /dashboard
     - Authenticated other routes → MainLayout with nested page

5) MainLayout renders:
     - Collapsible Sidebar (navigation)
     - Sticky Header (page title, search, clock, notifications, profile)
     - Main content area via React Router <Outlet />

6) Each page loads data via services (or module-local mock) and renders
   tables, KPIs, charts, filters, modals, and drawers.

7) User actions (filter, generate bill, export CSV, edit rate, add user)
   update local React state and/or mutate in-memory mock arrays.


================================================================================
8. AUTHENTICATION
================================================================================

File: src/context/AuthContext.tsx

Mechanism:
  - Simple client-side demo authentication
  - Hardcoded credentials: admin / admin123
  - On success: sets localStorage "aocc_auth" = "true"
  - Stores user object: { name: "Admin User", username: "admin" }
  - logout() clears localStorage and resets state

ProtectedRoute (in AppRoutes.tsx):
  - Reads isAuthenticated from useAuth()
  - If false → <Navigate to="/login" />
  - If true → renders children (MainLayout)

Login page:
  - Airport-themed split layout (hero + form)
  - Validates credentials via AuthContext.login()
  - On success navigates to /dashboard

NOTE: This is NOT production-grade security. There is no JWT, no server
session, and credentials are hardcoded for demo purposes only.

10.1 LOGIN & ACCESS CONTROL
--------------------------------------------------------------------------------

What it is:
  Entry gate for the Telecom Portal. Only authenticated users reach the
  operational console.

Functionalities:
  - Username / Employee ID + password sign-in form
  - Show / hide password toggle
  - Remember Me checkbox (UI)
  - Forgot Password link (UI placeholder)
  - Validation messages for empty or invalid credentials
  - Demo credentials displayed for training / UAT use
  - Airport-branded hero panel with network stats (PBX trunks, extensions,
    daily volume)

How it works:
  On submit, AuthContext checks credentials. Success stores auth flag in
  localStorage and routes to Dashboard. Failure shows an error banner.
  Logout (sidebar or header) clears auth and returns to Login.

Who uses it:
  Telecom admins, billing managers, and other portal roles (role model
  exists in Users; login itself is currently a single demo admin account).

10.4 CDR RECORDS — CALL DETAIL RECORD BROWSER
--------------------------------------------------------------------------------

What it is:
  The master call log. Every telephone call (or attempt) can be searched,
  filtered, inspected, and selected for further action.

Functionalities:
  A) Summary KPIs for the filtered set
     - Total records, completed, failed, total duration, total billing

  B) Text search (multi-field)
     Searches across: CDR ID, user name, extension, device ID,
     destination name, destination number, department

  C) Quick filters (one-click)
     - All
     - Internal
     - External
     - International
     - Completed
     - Failed
     - High Billing (amount above threshold)
     - Long Duration (long talk-time calls)

  D) Advanced filters
     - Date presets and custom from/to dates
     - Time window (fromTime / toTime)
     - Extension mode: all / single / multiple / range
     - Department, Device
     - Call type, Call status
     - Min/max duration (seconds)
     - Min/max amount (₹)

  E) Records table
     - Chronological call list with direction, parties, type, duration,
       status, billing amount
     - Row selection (single / multi / select all filtered)
     - Open detail drawer

  F) CDR Detail Drawer
     - Full caller & destination metadata
     - Device / location info
     - Tariff, rate, cost, tax, total
     - Disconnect reason / call status
     - Related CMR quality summary when available
       (score, packet loss, jitter, latency)

  G) Reset filters
     - One action restores default search + filter state

Business value:
  Audit any call, investigate high-cost destinations, or prepare filtered
  sets for export / billing disputes.

  Companion dataset to CDR focused on voice quality and network health

Functionalities:
  A) Quality KPIs
     - Total CMR records
     - Good / Fair / Poor counts
     - Quality issues count
     - Average quality score, jitter, packet loss

  B) Quick filters
     - Excellent / Good / Fair / Poor
     - Quality issues
     - High jitter / high packet loss / high latency

  C) Advanced filters
     - Date/time range
     - Quality status & issue type
     - Extension, department, device
     - Min/max quality score

  D) Multiple view tabs
     - Records table
     - Quality issues table
     - Department quality summary
     - Device quality summary
     - Quality distribution

  E) Detail drawer
     - Codec / media stats
     - Packet counts, RTT, latency, jitter
     - Issue severity, recommended action
     - Minute-by-minute QoS time series
     - Link back to related CDR billing summary

Business value:
  Separate “expensive call” problems (billing) from “bad audio” problems
  (network / device), and find which departments or phones cause issues.

     - Airport code
     - Currency / symbol (INR / ₹)
     - Time zone

  B) Billing
     - Default GST / tax rate (%)
     - Billing cycle day of month
     - Grace period (days)
     - Rounding rule

22. BILLING CALCULATIONS
================================================================================

Formula (client utility):

  pulses = ceil(durationSeconds / pulseSeconds)
  billableMinutes = (pulses * pulseSeconds) / 60
  subtotal = billableMinutes * ratePerMinute
  taxAmount = subtotal * (taxPercent / 100)     // default 18% GST
  totalAmount = subtotal + taxAmount

Internal calls are typically free (rate 0).
Rate Plans page includes a live calculator to demonstrate this logic.

Invoice totals on Billing page come from billingService.generateBill()
which currently returns precomputed demo numbers for the new period.
